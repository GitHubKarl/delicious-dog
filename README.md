# 美食转盘 · delicious-dog

给选择困难症用户的「今天吃什么」小程序：**每顿饭不知道吃什么，就转一下。**

## 一句话说明

首页一个大转盘，点击转动，随机落一个吃饭品类（火锅 / 川菜 / 日料…）。转盘上的品类数量有上限，用户可自选常吃的那些。

**首期定位：纯离线、个人主体、不登录、不采集任何用户数据。** 先验证有没有人愿意用，再谈云端。

## 快速开始

```bash
cd frontend
unset NODE_OPTIONS          # 本机必须，见下方「环境注意」
npm install
npm run dev:mp-weixin       # 产物 dist/dev/mp-weixin
```

用微信开发者工具导入 `frontend/dist/dev/mp-weixin`，appid 选「测试号」（`manifest.json` 里的 appid 还没填）。

只想看页面效果：`npm run dev:h5` 直接在浏览器打开，不用开开发者工具。

## 已确定的决策

| 决策点 | 结论 | 原因 |
|---|---|---|
| 品类粒度 | 吃饭类型（火锅/川菜…），不是具体菜名 | 最贴合「解决纠结」，词库也小 |
| 品类数量 | 3~12 个，默认 8 个 | 扇区太小文字看不清；少于 3 个转盘没意义 |
| 结果交互 | 弹出结果卡片 + 「再转一次」 | 最简闭环，不加确认步骤 |
| 工程方式 | CLI（Vite）而非 HBuilderX | 可自动化、可验证编译、git 干净 |
| 转盘实现 | `conic-gradient` + CSS `rotate` | 扇区数量变化只改渐变串，不用重绘 canvas |
| 后端 | SCA 选型已定，单机版优先，暂不启动 | 离线版没有需要后端的能力 |

## 产品约束（不可随意突破）

- **不采集用户数据**：没有登录、没有埋点、没有上报接口
- **离线可用**：断网状态下功能完整，数据只在本地 storage
- **个人主体**：依赖微信登录、支付等能力前要先确认主体资质
- **单页承载**：首期所有交互在首页完成，不铺多页面
